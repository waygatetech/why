## Question

tix approve's hook writes human-provenance decision files into the working tree, so the done-time `why check` against the merge base would flag exactly those files. How does check tell approved files from forged ones?

## Ruling

receipts in the git common dir

## Why

No tix or git workflow change, survives worktrees, and any edit after approval changes the hash so it fails. An agent with shell can forge a receipt on purpose, but won't do it by accident, which is the stated threat. Committing to main from a hook is surprising; ignoring new files drops half the ticket.
