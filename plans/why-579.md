Rulings (Brian, 2026-10-08): ruling = `recommend` at approval time; IDs = `<ticket>-<n>`.

- `internal/plan`: `Decisions(path) (ticket, concepts, []Entry, error)`; Entry{Q, Options, Recommend, Why}. Lenient YAML (tix owns the schema; ignore other keys).
- `internal/decision` (store): `Load(dir) ([]Decision, error)` (missing dir = empty), `Active([]Decision) []Decision` (drops IDs listed in any supersedes), `NextID(ds, ticket)`, `Write(dir, d)` creating decisions/ and refusing to overwrite.
- `record.go`: `--from-plan` maps each entry to Question=q, Ruling=recommend, Why=why, Concepts=plan concepts, Ticket=plan ticket. Re-running on the same plan skips entries whose (ticket, question) already exists, so a re-approve is idempotent. Single mode: flags, or a decision file on stdin when --ruling is unset. Date = today; decided_by from --decided-by, default `agent` (provenance enforcement is why-580). Prints written paths.
- `list.go`: active decisions, filtered to any matching --concept, sorted by ID. text: `<id>  [concepts]  <ruling first line>`; md: `## <id>: <question>` + Ruling/Why, for vet --context.
- Root = repo.Root(cwd); decisions live in `<root>/decisions/`.

Tests: table-driven store tests (Load/Active/NextID/Write no-clobber), plan parsing, and a cli_test running record --from-plan then list in a temp repo.
